# 资源占用实测台账

每台机器的数字都不一样，这里全部是**本机实测**（CachyOS，kwin 6.7.5，Wayland，
eDP-1 1536x960 @dpr2.0 + DP-1 1920x1080 @dpr1.0）。口径写在每条后面。

## 进程

| 进程 | RSS | 空载 CPU | 口径 |
|---|---|---|---|
| `codeisland-bridge` | 短命进程，342 KB 二进制 | 启动中位 0.29 ms | 60 次 `subprocess.run` 墙钟中位数，走 socket 不存在这条最常见路径 |
| `codeisland-daemon` | 2.5 MB | 10 秒内 0.000 秒 | `ps -o rss`；CPU 取 `/proc/<pid>/stat` 的 utime+stime 差值 ÷ `getconf CLK_TCK` |
| `codeisland-shell` | **98.7 MB** | 见下 | 软件渲染后端，空会话 |

## 界面（`codeisland-shell`）的两项关键选型

### 渲染后端：软件渲染

同负载、同一台机器、5 个会话：

| 后端 | RSS | 动画期间 CPU |
|---|---|---|
| GL（默认） | 174.3 MB | 15.8% 单核 |
| **software** | **98.7 MB** | 17.0% 单核 |

CPU 差 1.2 个百分点，内存省 75 MB → 默认改软件渲染（`main.cpp` 里 `qputenv` 仅在
`QT_QUICK_BACKEND` 为空时填值，所以仍可被环境变量覆盖）。

另外量到 **Qt Quick 自身的内存地板很大**：只含一个 `Window` + 一个 `Rectangle` 的
最小程序，GL 后端下 RSS 就是 143.9–149.5 MB。所以 98.7 MB 里几乎不是我代码的成本。

### 动画：单个标记闪烁，而不是每张卡片各自脉动

这是本项目最大的一次 CPU 浪费修正，全部实测（软件后端，5 个会话等批准，岛展开）：

| 做法 | 持续 CPU |
|---|---|
| 每个圆点一条 `SequentialAnimation on scale`（60 fps 无限循环） | **15.25% 单核** |
| 每个圆点离散闪烁 + `Behavior on opacity` 插值 | **6.00% 单核** |
| **只有头部一个标记闪烁**，卡片静态着色 | **0.80% 单核** |

根因不是动画计算，而是**重绘面积**：表面铺满整条屏幕宽（3072 物理 px），每个动画
节点都在让整个表面变脏。一个 700 ms 的开关计时器只产生 1.4 次/秒重绘。

对照基准：
- 空岛（计时器不跑）：**0.00% 单核**
- 5 个会话但岛收起（只有 1 Hz 时间戳定时器在跑）：**0.12% 单核**

**为什么这条值得较真**：一个等批准的会话可以挂几分钟甚至几十分钟——那正是这个工具
的存在理由。所以"静止显示时"的 CPU 不是瞬时开销，是持续开销。

## 事件吞吐

| 指标 | 实测 | 口径 |
|---|---|---|
| 常驻程序事件吞吐 | 28266 事件/秒，平均 0.04 ms | 单线程循环发 1000 个真实 socket 连接 |
| 权限请求往返（无界面可答） | **1.5–1.7 ms** | 真实 bridge 二进制，daemon 在跑但没有 UI |
| 桌面通知的代价 | 空闲 3 线程 / 2708 kB → 连发 6 次后 **仍是 3 线程** / 2940 kB | `/proc/<pid>/status`，2026-10-14 |

最后一条是安全契约的直接体现：没有界面可问时**必须**立刻沉默，绝不能把 agent 挂住。

通知那条为什么单独测线程数：发送被放到独立线程，且卡死的发送进程会在 3 秒处被杀掉。
线程数不随通知次数增长，就是"没有一发通知攒一条线程/一个僵尸进程"的直接证据——
这台机器上通知服务缺席时 `notify-send` 会挂 25~60 秒，不杀就会一直堆。

## 度量方法本身也需要测

`scripts/visual-check.py` 早期版本用"变暗差分"定位胶囊，在深色壁纸上只测到 5 px 高
（背景亮度 46，近黑胶囊的差分量不到阈值）。改成**绝对近黑判据**（`luma < 20` 且比
之前暗）后，测得 516x66 物理 px = 258x33 逻辑 px，与 QML 要求的 260x34 对上。

另一次教训：差分法必须先做**抖动标定**——连拍两张无人操作的图，把变化的像素排除。
第一版没做，把自己终端的输出当成了胶囊，"找"到 6383x1793 的变更区域（整块屏幕）。

## 复现

```bash
cargo build --release
cmake -B shell/build -S shell -G Ninja && ninja -C shell/build
uv run --with pillow --with numpy --python 3.12 -- scripts/visual-check.py
python3 scripts/view-probe.py
./scripts/smoke-claude.sh        # 会真实调用 claude（模型钉在 haiku）
```

CPU 采样口径：读 `/proc/<pid>/stat` 的 utime+stime，间隔 10 秒取差，除以
`getconf CLK_TCK`，再除以墙钟间隔。单核百分比，不是整机百分比。

## 界面进程（`codeisland-shell`）的实测

阶段 1 建好界面后补测。机器：CachyOS，kwin 6.7.5，Wayland，
eDP-1 1536x960 @dpr2.0 + DP-1 1920x1080 @dpr1.0。

| 指标 | 实测 | 口径 |
|---|---|---|
| RSS（软件渲染） | **98.7 MB** | `ps -o rss`，空会话 |
| RSS（GL 渲染） | 174.3 MB | 同一负载下对比测得 |
| Qt Quick 内存地板 | 143.9–149.5 MB | 只有一个 `Window` + 一个 `Rectangle` 的最小程序，GL 后端。**说明 98.7 MB 里几乎不是我代码的成本** |
| 空岛 CPU | **0.000 秒 / 10 秒** | `/proc/<pid>/stat` utime+stime 差值 ÷ `getconf CLK_TCK` |
| 5 会话、岛收起（1 Hz 时间戳定时器在跑） | 0.12% 单核 | 同上口径，10 秒窗口 |
| 5 会话等批准、岛展开、单标记闪烁 | **0.80% 单核** | 同上 |
| 仅 1 会话等批准 | 0.70% 单核 | 同上 |
| 权限请求往返（daemon 在跑、无界面可答） | **1.5–1.7 ms** | 真实 `codeisland-bridge` 二进制，stdout 必须为空 |

### 两个由实测决定的选择

**渲染后端用软件渲染。** 同负载 5 个会话：GL 是 174.3 MB / 15.8% CPU，software 是
98.7 MB / 17.0% CPU。CPU 只差 1.2 个百分点，内存省 75 MB。`main.cpp` 里只在
`QT_QUICK_BACKEND` 为空时填默认值，所以想比较仍可导出环境变量覆盖。

**闪烁只闪烁一处。** 这条是本项目最大的一次 CPU 浪费修正，三轮实测（软件后端、
5 个会话等批准、岛展开）：

| 做法 | 持续 CPU |
|---|---|
| 每个圆点一条 `SequentialAnimation on scale`（60 fps 无限循环） | 15.25% 单核 |
| 每个圆点离散闪烁 + `Behavior on opacity` 插值 | 6.00% 单核 |
| **只有头部一个标记闪烁**，卡片静态着色 | **0.80% 单核** |

根因不是动画计算，而是**重绘面积**：界面表面铺满整条屏幕宽（3072 物理像素），每个
动画节点都会让整个表面变脏。一个 700 ms 开关计时器只产生 1.4 次/秒重绘。

为什么值得较真：一个等批准的会话可以挂几分钟甚至几十分钟——那正是这个工具存在的
理由。所以"静止显示时"的 CPU 不是瞬时开销而是持续开销。

### 度量方法本身也要测

`scripts/visual-check.py` 有两个自己踩的坑，记下来防止再犯：

1. **差分法必须先做抖动标定。** 第一版比较"有窗口/无窗口"两张图，把自己终端的输出
   当成了胶囊，报告变更区域是 6383x1793（整块屏幕）。现在先连拍两张无人操作的图，
   把其间变化的像素排除掉。
2. **"变暗差分"在深色壁纸上会漏测。** 壁纸亮度中位数只有 46，近黑胶囊的差分量不到
   阈值，结果胶囊只测到 5 px 高。改成绝对判据（`luma < 20` 且比之前暗）之后测得
   516x66 物理像素 = 258x33 逻辑像素，与 QML 要求的 260x34 对上；展开态
   1236x417 = 618x209，与 QML 的 620 宽、`54 + 2x78 = 210` 高对上。
